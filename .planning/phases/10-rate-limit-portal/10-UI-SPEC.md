## Interaction Contract

### New Table Columns (RATE-05)

Three columns added to `KeyTable.tsx`, inserted between "Usage" and "Actions":

| Column Header | Data Field | Render Rule |
|---------------|------------|-------------|
| Rate/min | `rate_limit_per_minute` | If 0 → display text `Unlimited`; else display the integer |
| Rate/day | `rate_limit_per_day` | If 0 → display text `Unlimited`; else display the integer |
| Today | `day_usage` | Always display the integer (0 if no requests today or no day limit set) |

Column header class: `text-xs font-normal` (matches existing headers).
Cell class: `text-sm` (matches existing cells).

Column count before: 7. Column count after: 10. Both `<TableHead>` entries and `<TableCell>` entries must be updated together to prevent column misalignment.

### TypeScript Interface Addition (RATE-05)

Add `day_usage: number` to the `KeyResponse` interface in both:
- `web/src/components/KeyTable.tsx`
- `web/src/components/EditKeyDialog.tsx` (for consistency, even though dialog does not render it)

### Edit Dialog (RATE-06)

`EditKeyDialog.tsx` is already complete. The rate limit fields (`rateLimitPerMinute`, `rateLimitPerDay`) are already wired with state, form inputs, and PATCH body logic. No UI changes required for RATE-06.

Input IDs for the existing fields (for reference/testing): `edit-key-rpm`, `edit-key-rpd`.

### Loading State

No change to existing loading skeleton. The three new columns will be covered by the same `Skeleton` rows since they span the full table width.

### Empty State

No change. Existing empty state copy remains.

## States and Edge Cases

| State | Element | Behavior |
|-------|---------|----------|
| Key has no rate limits set (both fields = 0) | Rate/min, Rate/day cells | Display "Unlimited" (not "0") |
| Key has rate limit but no requests today | Today cell | Display `0` |
| Key has per-day limit and some requests today | Today cell | Display the count as returned by `day_usage` from the API |
| Server just restarted (counter reset) | Today cell | Display `0` — reset on restart is acceptable per REQUIREMENTS.md |
