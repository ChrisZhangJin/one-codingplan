GREEN phase -- implement internal/pool/pool.go:

Package `pool`. Define:

```go
type UpstreamEntry struct {
    ID      uint
    Name    string
    BaseURL string
    APIKey  string
}

type entry struct {
    UpstreamEntry
    available bool
}

type Config struct {
    RateLimitBackoff time.Duration
}

type Pool struct {
    mu      sync.RWMutex
    entries []entry
    idx     int
    cfg     *Config
    stopCh  chan struct{}
}

var ErrNoUpstreams = errors.New("pool: no available upstreams")
```

`New(db *gorm.DB, encKey []byte, cfg *Config) (*Pool, error)`:
1. `db.Where("enabled = ?", true).Find(&upstreams)` using `[]models.Upstream`
2. For each upstream, call `u.DecryptAPIKey(encKey)` to get plaintext key
3. Build `[]entry` with `available: true`
4. Create Pool struct with `stopCh: make(chan struct{})`
5. Do NOT start probe goroutine yet (that is Plan 02)
6. Return pool

`Select(keyID string) (*UpstreamEntry, error)`:
1. `p.mu.Lock()` / `defer p.mu.Unlock()` (write lock because it mutates idx)
2. `n := len(p.entries)`; if n == 0 return ErrNoUpstreams
3. Loop `i := 0; i < n; i++`: advance `p.idx = (p.idx + 1) % n`; if `p.entries[p.idx].available`, return a copy of `p.entries[p.idx].UpstreamEntry`
4. If loop exhausts, return ErrNoUpstreams

`Mark(id uint, available bool)`:
1. `p.mu.Lock()` / `defer p.mu.Unlock()`
2. Linear scan `p.entries` for matching `id`, set `available` field

`Stop()`:
1. Close `p.stopCh` (idempotent via sync.Once or select-default pattern)

`Backoff() time.Duration`:
1. Return `p.cfg.RateLimitBackoff`

Note on keyID parameter: per D-17, Select accepts keyID for future per-key pool restriction (Phase 5 KEY-05). For now, ignore keyID and select from the full pool. Do NOT add key-filtering logic.

Run `go test -race -count=1 ./internal/pool/...` -- all 7 tests must pass.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| upstream API response -> classifier | Untrusted response body from external API parsed for classification |
| SQLite -> pool | Upstream records loaded from DB at startup; DB is admin-controlled |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | D (DoS) | classifier body read | mitigate | Classifier receives `[]byte` body already read by caller; document that caller must use `io.LimitReader(resp.Body, 64*1024)` when reading (enforced in Plan 02 probe and Phase 3 relay) |
| T-02-02 | I (Info Disclosure) | pool entry.apiKey | mitigate | Never log `entry.APIKey`; log `entry.Name` only. No `fmt.Sprintf("%+v", entry)` patterns that would dump the key. Pool tests use fake keys `"sk-testname"`. |
| T-02-03 | I (Info Disclosure) | encryption key in memory | accept | `encKey []byte` passed to New() and used once for decryption; held transiently on stack. Decrypted API keys held in Pool.entries for the process lifetime — acceptable for single-instance server with no shared memory. |
| T-02-04 | T (Tampering) | classifier keyword map | accept | Package-level `var` is writable at runtime but only by code in the same process. No external input modifies the map. Acceptable for single-binary deployment. |
</threat_model>
