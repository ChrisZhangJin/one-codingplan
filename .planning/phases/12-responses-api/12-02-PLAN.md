```go
package translator

import (
    "bytes"
    "encoding/json"
    "fmt"
)

// ResponsesStreamTranslator translates OpenAI SSE chunks to Responses API SSE events.
// It is stateful: tracks whether opening events have been emitted, accumulates text
// for done events, and maintains a monotonic sequence_number counter.
type ResponsesStreamTranslator struct {
    model       string
    responseID  string
    messageID   string
    started     bool
    seqNum      int
    accumulated []byte
    buf         []byte
}

func NewResponsesStreamTranslator(model string) *ResponsesStreamTranslator {
    return &ResponsesStreamTranslator{
        model:      model,
        responseID: "resp_proxy",
        messageID:  "msg_proxy",
    }
}
```

The `Translate(chunk []byte) ([][]byte, error)` method must:
1. Append chunk to buf, scan for complete SSE frames (`\n\n` delimiter) -- identical frame-buffering logic as `StreamTranslator.Translate()`
2. For each frame, extract the `data: ` line, skip non-data lines
3. Handle `[DONE]` sentinel: emit closing sequence (output_text.done, content_part.done, output_item.done, response.completed) with accumulated text
4. Parse `openAIStreamChunk` (reuse the same struct shape from stream.go or define locally)
5. If content is non-empty and `!started`: emit opening events (response.created, response.output_item.added, response.content_part.added), set started=true
6. If content is non-empty: emit `response.output_text.delta` with the delta text, append to accumulated
7. If finish_reason is non-null and non-empty: emit closing sequence
8. Each event increments `seqNum`; the `sequence_number` field in each event JSON is set to the current seqNum value

Use `formatSSEEvent` from `stream.go` (already exported at package level) for formatting SSE events. Each event's `data` payload must include `"type"` matching the event name and `"sequence_number"` set to the current seqNum.

The `handleResponsesRelay` method on `*Server`:
- Read body with `io.LimitReader(c.Request.Body, 10*1024*1024+1)`, reject >10MB with 413 using `responsesError("invalid_request_error", "request body too large")`
- Parse into `translator.ResponsesRequest` via `json.Unmarshal`; on error return 400 with `responsesError("invalid_request_error", "invalid JSON: "+err.Error())`
- Call `translator.ParseResponsesInput(req.Input)`; if error is `translator.ErrStringInput`, return 400 with `responsesError("invalid_request_error", "input must be an array")`; if other error, return 400
- Get keyID and accessKey from context (same as anthropic.go)
- Call `parseAllowedUpstreams(accessKey.AllowedUpstreams)`
- Run the failover loop (copy from `handleAnthropicRelay` in anthropic.go):
  - `s.pool.Select(allowedUpstreams)` to get upstream
  - Track `seen` map to detect exhaustion
  - Build `sendBody` by marshaling `translator.ResponsesRequestToOpenAI(&req, msgs, "")` to JSON; if `up.ModelOverride != ""`, pass it as the modelOverride parameter instead of rewriting JSON
  - Create `outReq` to `pool.GetAdapter(up.Name).OpenAIURL(up.BaseURL)` (upstream receives OpenAI chat completions format)
  - Set headers: `Authorization: Bearer <up.APIKey>`, `Content-Type: application/json`, delete Host
  - Execute with `relayClient.Do(outReq)`
  - Handle errors (4xx/5xx) with same classify/mark/backoff pattern as anthropic.go
  - On success: branch on `req.Stream`:
    - If streaming: call `s.proxyResponsesStream(c, resp, cancel, keyID, up.ID, start, req.Model)`
    - If non-streaming: read response body, parse as `translator.OpenAIResponse`, call `translator.OpenAIToResponsesAPI(&openAIResp, req.Model)`, marshal and return as JSON with 200
  - If all upstreams exhausted: return 503 with `responsesErrNoUpstream`

The `proxyResponsesStream` method (modeled on `proxyStream` in relay.go):
- Same signature as proxyStream plus `model string` parameter
- Set streaming headers: `Content-Type: text/event-stream`, `X-Accel-Buffering: no`, `Cache-Control: no-cache`, `Connection: keep-alive`
- WriteHeader 200
- Get flusher
- Create mutex-guarded writeAndFlush (same pattern as proxyStream)
- Start heartbeat goroutine (same pattern as proxyStream, using HeartbeatInterval)
- Create `translator.NewResponsesStreamTranslator(model)`
- Read upstream body in 4096-byte chunks
- For each chunk: call `translator.Translate(chunk)`, for each emitted event call `writeAndFlush(event)`
- On EOF/error: break
- Log usage with `s.logUsage(keyID, upstreamID, true, 0, 0, ...)`

For the **non-streaming response path**, do NOT use `proxyBuffer` (it forwards raw bytes). Instead:
- Read the full upstream response body
- Parse as `translator.OpenAIResponse` via `json.Unmarshal`
- Call `translator.OpenAIToResponsesAPI(&openAIResp, req.Model)`
- Marshal the ResponsesResponse to JSON
- Write with `c.JSON(http.StatusOK, responsesResp)`
- Extract token counts from the OpenAI response usage for `logUsage`

## Trust Boundaries

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-01 | Elevation | handleResponsesRelay | high | mitigate | Route registered in v1 Gin group which applies `authMiddleware` + `limitMiddleware`; auth validates bearer token against DB; missing/invalid token returns 401 |
| T-12-02 | Denial of Service | handleResponsesRelay | high | mitigate | Body size capped at 10MB via `io.LimitReader(body, 10*1024*1024+1)`; oversized returns 413 |
| T-12-03 | Information Disclosure | handleResponsesRelay | high | mitigate | Upstream API key set via `outReq.Header.Set("Authorization", "Bearer "+up.APIKey)` replacing client auth header; client's token never forwarded to upstream |
| T-12-04 | Tampering | handleResponsesRelay | medium | mitigate | `input` JSON type validated before parsing (D-02); only `model`, `messages`, `stream` fields built into upstream request (D-01, D-04: tools/tool_choice structurally excluded by building OpenAIRequest from explicit fields only) |
| T-12-05 | Tampering | instructions field | low | accept | ocp passes instructions as system message content to upstream; prompt injection is upstream's responsibility, not the proxy's |
| T-12-06 | Denial of Service | proxyResponsesStream | medium | mitigate | 30-second upstream request timeout via `context.WithTimeout`; heartbeat goroutine keeps client connection alive during slow streams; stream translator processes fixed-size chunks |
</threat_model>
