<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> /api/* | Untrusted HTTP request; must carry valid admin Bearer token |
| admin.go -> DB | Handler writes user-supplied values to SQLite via GORM parameterized queries |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-01 | Spoofing | adminMiddleware | mitigate | Use `crypto/subtle.ConstantTimeCompare` for admin key comparison to prevent timing attacks; reject missing/wrong tokens with 401 |
| T-5-02 | Tampering | handleUpdateKey | mitigate | Use GORM parameterized queries (never raw SQL interpolation); validate field types via `ShouldBindJSON` typed struct |
| T-5-03 | Information Disclosure | handleListKeys/handleGetKey | mitigate | Mask token via `maskToken()` on all GET responses per D-14; full token only on POST /api/keys response |
| T-5-04 | Information Disclosure | adminMiddleware | accept | Admin key is in config; a single admin user; no multi-tenant enumeration risk |
| T-5-05 | Denial of Service | handleListKeys | accept | No pagination (D-11); at personal scale key count is <100; no mitigation needed |
| T-5-06 | Tampering | handleCreateKey | mitigate | Key name validated as string by Go type system; AllowedUpstreams is `[]string` — no arbitrary injection path; UUID IDs are not guessable |
| T-5-07 | Elevation of Privilege | /api/* routes | mitigate | /api/* group uses adminMiddleware (D-02); /v1/* uses separate authMiddleware; no cross-contamination |
</threat_model>
