<objective>
Add `ClassModelNotSupported` to the error classifier so that upstreams returning
model/config errors (e.g., MiniMax "not support model") are permanently marked
unavailable for the session instead of being retried on every request.

Purpose: Without this, a misconfigured upstream floods logs with repeated 400/500
errors on every request. Classifying model errors like credits exhaustion prevents
the retry storm.

Output: New constant in classifier.go, keyword table for model/config errors,
updated switch cases in both relay handlers, and tests covering the new class.
</objective>

In `Classify`, add the model/config check BEFORE the existing keyword loop (so it
runs first and can claim 5xx bodies before the credits keywords run):

```go
func Classify(provider string, status int, body []byte) ErrorClass {
    bodyStr := strings.ToLower(string(body))

    // Model/config errors: 5xx only (ROUT-05)
    if status >= 500 {
        for _, kw := range modelNotSupportedKeywords {
            if strings.Contains(bodyStr, kw) {
                return ClassModelNotSupported
            }
        }
    }

    // Credits exhaustion check (existing — must run before 429 rule)
    keywords := defaultCreditsKeywords
    if overrides, ok := providerCreditsKeywords[provider]; ok {
        keywords = overrides
    }
    for _, kw := range keywords {
        if strings.Contains(bodyStr, kw) {
            return ClassCreditsExhausted
        }
    }

    if status == 402 {
        return ClassCreditsExhausted
    }
    if status == 429 {
        return ClassRateLimited
    }
    return ClassTransient
}
```
