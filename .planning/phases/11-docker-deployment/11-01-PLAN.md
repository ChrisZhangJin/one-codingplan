Wait — reviewing: Dockerfile says `ENTRYPOINT ["ocp", "serve"]` and compose says `command: ["serve", "--config", "/app/config.yaml"]`. In Docker, command replaces CMD, not ENTRYPOINT. Fix by changing Dockerfile ENTRYPOINT to `["ocp"]` and updating compose:
- `ocp` service command: `["serve", "--config", "/app/config.yaml"]` (this becomes `ocp serve --config /app/config.yaml`)

Actually wait — the compose `ocp-cli` service already sets `entrypoint: ["ocp"]` which overrides the Dockerfile ENTRYPOINT. So for ocp-cli, the command becomes args to `ocp`. That's fine. The problem is only the `ocp` service where ENTRYPOINT + command doubles `serve`.

Resolution: In the Dockerfile, change `ENTRYPOINT ["ocp", "serve"]` to `ENTRYPOINT ["ocp"]` and `CMD ["serve"]`. Then compose `command: ["serve", "--config", "/app/config.yaml"]` overrides CMD and produces `ocp serve --config /app/config.yaml`. For ocp-cli, `entrypoint: ["ocp"]` + `command: ["--help"]` produces `ocp --help`. This is correct.

So change Dockerfile last two lines to:
```dockerfile

```

2. Add `depends_on: [ocp]` to the `ocp-cli` service so the network and ocp container exist when CLI runs.

3. Add `env_file: .env` to the `ocp` service (optional convenience — users can use `environment:` block or `.env` file). Actually, compose auto-reads `.env` in the project directory for variable interpolation, so `${OCP_ENCRYPTION_KEY}` already works if `.env` exists. No change needed here.

4. Add `OCP_ADMIN_KEY: ${OCP_ADMIN_KEY}` to the `ocp` service environment block. Currently the admin key is only in config.yaml, but if the user wants to override via env var, the config loader supports `OCP_SERVER_ADMIN_KEY` (env prefix OCP + key server.admin_key = OCP_SERVER_ADMIN_KEY). Actually, looking at config.go: `v.SetEnvPrefix("OCP")` and `v.SetEnvKeyReplacer(strings.NewReplacer(".", "_"))` means `server.admin_key` maps to `OCP_SERVER_ADMIN_KEY`. The compose already passes `OCP_ENCRYPTION_KEY` via env. The admin_key is in the mounted config.yaml, which is fine.

No additional env vars needed for ocp service beyond what's there.

Final docker-compose.yaml:
```yaml
services:
  ocp:
    build:
      context: .
      dockerfile: Dockerfile
    image: one-codingplan:latest
    container_name: ocp-server
    restart: unless-stopped
    ports:
      - "8080:8080"
    volumes:
      - ./data:/data
      - ./config.yaml:/app/config.yaml:ro
    environment:
      OCP_ENCRYPTION_KEY: ${OCP_ENCRYPTION_KEY}

  ocp-cli:
    image: one-codingplan:latest
    container_name: ocp-cli
    profiles:
      - cli
    depends_on:
      - ocp
    environment:
      OCP_HOST: ${OCP_HOST:-http://ocp:8080}
      OCP_ADMIN_KEY: ${OCP_ADMIN_KEY}
    networks:
      - default
    entrypoint: ["ocp"]
    command: ["--help"]

networks:
  default:
    name: ocp-network
```
